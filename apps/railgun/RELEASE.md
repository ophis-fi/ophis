# Private swap release

This release integrates the reviewed runtime inside `swap.ophis.fi`, using the existing Ophis swap page and supplied incognito icon. It does not restore `private.ophis.fi`. The private fee is 10 bp (0.1%) of final swap output; the public SDK remains at 1 bp. No new contract deployment, SDK release or f(x) work is included.

## Release order

1. Pass the applicable source reviews, unit/security regressions, TypeScript checks, production builds and hosted checks. Assess outstanding dependency advisories using [DEPENDENCIES.md](./DEPENDENCIES.md) and [MULTICHAIN-REVIEW.md](./MULTICHAIN-REVIEW.md).
2. Build the runtime with `VITE_RAILGUN_ENVIRONMENT=mainnet`, `VITE_RAILGUN_ASSET_BASE=/private/` and the existing public WalletConnect project ID. Build the frontend with the private feature flag and run `node scripts/stage-private-swap.mjs`. Check the staged production bundle, not an earlier preview.
3. Merge the reviewed changes on Ophis's actual default branch, `main`. Keep `REACT_APP_PRIVATE_SWAP_ENABLED` unset until the gateway passes its deployment checks.
4. Set the protected Production environment's server-only `RAILGUN_ZAN_API_KEY`, `RAILGUN_ARBITRUM_RPC_URL`, `RAILGUN_POLYGON_RPC_URL` and `RAILGUN_BNB_RPC_URL`, preserving `RAILGUN_RPC_TOKEN`. The three URL secrets contain the corresponding Validation Cloud network keys. Run **Deploy private swap RPC** on `main`. It checks all upstreams, deploys `ophis-private-rpc` and its persistent budget binding on `swap.ophis.fi/rpc*`, installs the secrets in one update and checks all four deployed networks. Existing forwarding remains enabled during this update; old ZAN routing works until the new URL secrets are installed.
5. After gateway postflight succeeds, set repository variable `REACT_APP_PRIVATE_SWAP_ENABLED=true` and run **Deploy to Cloudflare Pages** on `main`. Verify both public and private swap pages, the supplied icon, mobile layout, CSP, iframe and WASM assets. Verify unsupported chains and administrative RPC methods fail closed. Never use a user's wallet or broadcast a funded transaction for deployment verification.

WalletConnect uses the existing public `REACT_APP_WC_PROJECT_ID`, with `swap.ophis.fi` allowed by Reown. Wallet storage belongs to the browser origin: a localhost wallet does not automatically appear on the production domain. Its owner restores it locally using their own recovery phrase. Never send that phrase to an operator or support channel.

## Runtime and provider boundaries

Public-to-private navigation loads a fresh document. Private entry skips GA4, Sentry and service-worker registration; wallet databases, journals and proof artifacts are preserved during existing public storage migrations. Private responses prohibit remote scripts, disable framing by other origins, set no-store and no-referrer headers, and separate public openers with COOP. The iframe has a separate module bundle but shares Ophis's first-party origin and storage trust. It is not isolation from a compromised same-origin application.

Ethereum uses Baal's synced node through the existing authenticated `https://railgun-rpc.ophis.fi/rpc` transport. Arbitrum, Polygon and BNB Chain use pinned server-only Alchemy URL secrets for reads, multicall quotes, estimates and recovery broadcasts. Alchemy Free rejects `debug_traceCall` and limits log ranges to ten blocks. Batches containing traces or log scans go directly to the selected network's pinned `RAILGUN_*_VALIDATION_CLOUD_URL` using its existing free allowance. Alchemy mode never contacts ZAN, including on failure. Provider selection happens before forwarding; execution is never retried through another provider. Both trusted providers may see a signed batch during separate call/trace checks. No subscription upgrade, paid overage or public fallback is configured. Existing non-Alchemy configurations retain legacy behavior for rollback.

Alchemy shares one persistent named Durable Object instance across all three chains. It allows 24M CU over a rolling 32 UTC days and 100 weighted throughput CU/second with a burst of 1,200, leaving 6M of the free account's 30M allowance for other usage and diagnostics. The 32-day window covers a monthly billing period without assuming its reset date. Twenty quote candidates use one Multicall `eth_call` (26 CU) instead of twenty individual calls (520 CU). Validation Cloud retains its separate 40M CU/calendar-month meter and 60 logical requests/second allowance. Every inner batch method reserves its published cost before forwarding; failures are not refunded. Unknown costs fail closed. These limits survive deployment and store only counts/dates; external account consumers are outside the meters and must fit the reserves. A budget-runtime failure returns a generic 503 identifying that stage without logging keys or payloads.

Deploy with the three Alchemy primary URL secrets and three Validation Cloud URL secrets in the protected Production environment. The preflight verifies both transports, canonical delegation, traces and 500-block logs before changing production, then repeats those checks through the deployed gateway. Never replace the working production configuration if preflight fails. A previous Validation Cloud rollout returned a generic 502 from the Worker despite direct upstream success; local runtime success does not establish that production incident is fixed. Confirm deployed checks or restore the recorded prior configuration before calling the rollout complete.

After uploading Worker code, deployment also probes the actual hosted meters **before** installing provider secrets. Protected `POST /rpc/budget/alchemy` and `/rpc/budget/validationCloud` require the existing deployment bearer, use native constant-time comparison of SHA-256 digests, and invoke only a fixed `eth_chainId` reservation. They never forward to a provider or accept execution calldata. Authorized diagnostics expose only bounded sanitized error fields; normal public errors stay generic. `RAILGUN_READINESS_BUDGET_ONLY=1` restricts the credential destination to Ophis or loopback and requires capacity for one worst-case batch. A meter failure leaves the prior provider secrets in place.

The restricted gateway permits wallet RPC methods, 20-call batches and 256 KiB bodies. Limits per IP and Cloudflare location are 600 calls/minute and 10 traces/minute. Calls and estimates are capped at 30 million gas. Tracing requires `callTracer`, a five-second timeout and no custom tracer. Log queries require the selected network's pinned Railgun proxy and at most 500 explicit blocks. Administrative methods and redirects are rejected. Raw transaction submission supports user-signed recovery; the server has no signing key. Observability, workers.dev and preview URLs remain disabled.

## Validation and operational limits

Four isolated local forks passed native deposit, real proof generation, private swap, confirmed private output, journal cleanup and exact 0.1% recipient payment. Delegated calls and traces passed through the selected gateway on all four chains. Existing Ethereum live execution was previously user-confirmed; this release's added-chain proof tests use a guarded fork POI adapter and local sponsor. Live added-chain PPOI delivery and broadcaster acceptance remain external checks, not claims established by fork tests.

Only Spendable notes pay swaps and broadcaster fees. Public and ShieldPending funds do not count. Mainnet deposits require a fresh compatible broadcaster offer, and swap preparation also checks the receive asset. Polygon native USDC had no compatible offer during final discovery; its deposit and receive paths block safely until availability changes.

The DEX trade and its amounts are public and can be sandwiched within the slippage limit. The trusted simulation RPC sees the signed executable batch and may submit it. A successful outer receipt alone is insufficient: execution checks committed private output and retains recovery journals until reconciliation. Dependency version scanning still reports advisories; reviewed browser reachability and backports are documented, not a zero-finding certification.

## Remaining MEV protection

Changing the read/simulation RPC does not configure how the Waku broadcaster signs and submits the final transaction. The current selection checks price, freshness and canonical delegation; it does not authenticate an operator's protected-submission policy. Before describing this route as MEV protected, identify a compatible operator per chain and verify its private submission transport, type-4 support, no-public-rebroadcast policy and failure/cancellation behavior. Pin verified broadcaster identities and fail closed if none offers a fresh compatible fee. Ethereum can use a Flashbots-compatible protected path; Polygon and BNB require compatible chain-specific relays, and Arbitrum's sequencer ordering must be assessed separately. An operator remains trusted not to leak orderflow; no absolute protection is claimed.

Prefer a suitable existing broadcaster. Running an Ophis broadcaster instead requires an operator-controlled gas signer, gas funding and a maintained service; application RPC credentials do not provide those. Validate exact signed calldata, enforced minimum output and private output reconciliation on forks, then verify an owner-signed live flow. No funded transaction is broadcast by the deployment checks.
