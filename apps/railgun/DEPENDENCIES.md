# Browser dependency review

This local prototype does not have a clean version-based dependency audit. At installation review the standalone production dependency audit reported 2 critical, 15 high, 12 moderate and 2 low findings. These counts include SDK Node-only branches, overlapping advisories on the same package, and locally patched versions. They are not evidence that every advisory executes in the browser, or that the dependency tree is approved for production.

The browser's actual Rollup module list was inspected, rather than treating every installed package as bundled. Full local evidence is in `/Users/scep/ophis-railgun-evidence/railgun-dependency-audit.json` and `bundled-modules.json` (machine-local paths, not application inputs).

`axios`, `ws` and `protobufjs` resolve through explicit patched-version overrides. Development tooling and proof artifacts are separate supply-chain concerns; Railgun's SDK validates downloaded artifact hashes. The application adds no custom cryptography or proof verifier.

The Waku web client's published peer range targets wallet `~11.1.0`; this package pins wallet 11.2.0 because it contains the nonce-aware 7702 APIs in use. Its explicit compatibility exception was tested with browser discovery of signed fresh fee advertisements, including the configured 7702 delegate. This does not establish successful live transaction acceptance. The published Waku archive contains no `.patch` or `patches/` files, so disabling its `patch-package` postinstall skips no shipped patch.

Before any release, rerun the standalone audit, inspect the current bundle, review the backports, and resolve or explicitly assess remaining reachable advisories. Do not use an all-green audit claim for this branch.

Follow-up checks on 2026-10-21 confirmed that these are the latest published Railgun wallet, engine, shared-model and Waku web-client versions. A regression now exercises the real Waku serializer and wallet11.2 encryption/decryption for both common and 7702 envelopes without sending them. Fresh signed compatible fee discovery also passed. The declared wallet peer-range exception remains; only a real broadcaster transaction can establish live acceptance. The standalone production audit was repeated outside the parent workspace and retained the same severity counts; the parent monorepo audit is not a substitute.

The release review corrected an omission in the earlier bundle inspection: legacy `ethjs-unit` and `number-to-bn` also bundled `bn.js` 4.11.6. An exact override now resolves that version to 4.12.5. A regression calls `maskn(0)` through both actual dependency paths and checks canonical zero without allowing the vulnerable implementation to enter its conversion loop. The rebuilt graph contains only 4.12.5 and 5.2.5. The existing elliptic backport also now has a deterministic P-521 leading-zero nonce regression.

After this fix, the standalone production audit reports **2 critical, 15 high, 11 moderate and 2 low** findings. The critical packages remain absent from the browser graph; bundled affected packages are patched or scoped in the table above. This is a browser-specific assessment, not approval to run the SDK's legacy Node branches or a claim that the version audit is clean. Current per-advisory evidence is in `/Users/scep/ophis-railgun-evidence/release-dependency-triage.json`.
