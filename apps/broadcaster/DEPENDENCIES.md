# Broadcaster dependency integration, 23 November 2026

This standalone Node service has its own lockfile. Browser bundle reachability and a green root-workspace audit do not establish its dependency safety. It now follows current Ophis's reviewed pnpm 10.34.9 pin, seven-day resolution age and scripts-disabled installation policy. Docker reads the integrity-pinned `packageManager` from the same manifest and includes `.npmrc` and every registered patch.

The engine 9.9.1, wallet 11.2.0, shared-models 8.2.1, ethers 6.14.3, snarkjs 0.7.5 and noble/ed25519 1.7.5 upstream archive versions/integrities are unchanged. The broadcaster excludes the wallet's unused React Native crypto shim dependency, removing elliptic and its otherwise unused dependency chain. The initial dependency checkpoint reproduced the pilot application bundle; later application changes have their own release hashes. External dependency changes are validated separately; matching application bytes alone is not a compatibility guarantee.

The 23 November standalone production pnpm audit found both GraphQL-utils and Zod advisories on the baseline and zero advisories on the updated lockfile. The broadcaster's CI audit removes those two exceptions. The picomatch exception expires on **17 December 2026**, and the workflow requires any package version covered by it to appear in `patchedDependencies`. Review the exception before expiry and after an SDK or bundler change.

The 4 November integration's seven-day age policy selected older eligible Babel/rolldown/browser-metadata transitive releases. That historical change is recorded in the integration evidence. The 18 November follow-up removes 21 unused packages and adds the picomatch patches without changing any remaining archive version or integrity. No broad cross-major uuid/minimatch overrides were copied from the browser project.

The 18 November verification passed frozen installation, 1,319 tests on Node 22 (12 optional integration tests skipped), typecheck/build, installed picomatch regressions and the Docker context canary. The original evidence remains in the private `integration-20261104` record. Further fee collection, repeat-user admission, hosted UX, operational monitoring and final release acceptance remain separate work in the development plan.
