# BNB mainnet pilot admission

The 6 November bounded BNB qualification exercised guarded type-4 inclusion, a known reverting transaction and an ordered pair whose second transaction reverts. The saved builder diagnostics identify the negative transactions; original and cleanup nonces were reconciled. Evidence is retained under `ophis-railgun-evidence/baal-replacement-20261106/bnb-qualification/`. These observations support a restricted pilot, not a guarantee of future builder behavior. A live user-paid RAILGUN swap and withdrawal with exact fee assurance on BNB remain outstanding.

The owner approved personally moving and shielding up to 0.002 BNB from the ANON gas reserve into a separate test wallet. This does not authorize an agent transfer or establish a completed test. The prepared pilot lowers the per-transaction cap to 0.00025 BNB and rolling-day cap to 0.00045 BNB, retains the 0.1 gwei gas-price cap and 15% minimum margin, and adjusts the reserve floor to 0.0175 BNB for that approved principal allocation. Activation still requires the owner's public pilot account and local unlock. Public clients exclude this operator on BNB until chain-specific public approval is installed.

`assertSigningNetwork` permits BNB mainnet only with `admission=pilot`. The same gate applies to startup, request handling and manual recovery. BNB public admission remains blocked even when an unarmed configuration is passed directly to recovery. Ethereum behavior is unchanged; Arbitrum and Polygon mainnet signing remain blocked. The existing independently approved, unarmed BNB guard commissioning path retains its separate approval and financial checks.

Enabling still requires an explicit pilot account, operator-bound guard, dedicated gas-wallet address, positive markup and explicit gas-price, transaction, rolling-budget and reserve limits. This change supplies no live addresses, budgets, key material or runtime override. Custody, chain-bound journals, WBNB-only fee authentication, exact guarded execution, nonce reconciliation, strict private bundle delivery and expiry remain unchanged. Mainnet original sponsored retries stay blocked; explicit bounded cancellation and retry of its identical signed bytes remain available for the pilot.

Pilot admission selects a swap account and optionally one USDC withdrawal recipient. It does not impose a one-swap count or bind the withdrawal's private wallet to that account. Without a withdrawal recipient, pilot withdrawals are rejected. The persisted withdrawal marker is a one-time gate; unavailable advertisements are not a substitute for stopping the service when the pilot ends. No service activation, owner unlock, funding or client release occurs through this source change.

Tests exercise each process chain explicitly for admission policy, missing BNB startup pins and limits, BNB public recovery rejection, and Ethereum/BNB mainnet recovery behavior. Run the broadcaster request suite separately with `OPHIS_BROADCASTER_CHAIN_ID=56` to exercise BNB assets and the mainnet-pilot request case. Existing general `core` and guard-deployment fixtures contain Ethereum-specific assumptions; running every legacy suite under a global BNB environment is not a valid substitute for the explicit per-chain tests.
