# OTC runtime signing switch

The **OTC runtime control** workflow runs only from protected `main`. The Pages credential reads the existing domain zone ID; the Workers Scripts/Routes credential deploys `ophis-otc-control` at `https://swap.ophis.fi/api/otc-control`, with a SQLite-backed Durable Object for one shared Ethereum switch. This avoids requiring R2 permissions. Other Pages routes are unchanged; workers.dev and preview URLs are disabled.

Before initialization, generate a random 32-byte hex credential and save it as the repository secret `OTC_CONTROL_TOKEN`. Never expose it to the browser, logs or the frontend build. Run `gh workflow run otc-runtime-control.yml --ref main -f mode=init`: this deploys the Worker and its secret together, writes disabled state, and verifies the public read endpoint. Initialization does not change wallet/token admission or enable frontend signing. Cloudflare may require an initialization retry while a newly uploaded Worker and route propagate; confirm a successful control run before activation.

To stop new signing, run `gh workflow run otc-runtime-control.yml --ref main -f mode=off`. Wait for success: the workflow authenticates the update and verifies the public endpoint with a fresh nonce. Durable Object storage is [strongly consistent](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/); endpoint and browser authorization reads are uncached. A failed read disables signing. Already-issued wallet prompts and signed transactions cannot be cancelled by this switch.

For a timed trial, use `mode=on` with `expires_at=YYYY-MM-DDTHH:MM:SSZ` within the next 24 hours. Both the operator and server enforce that bound. For public service, use `mode=public` without an expiry: it writes the explicit `{ enabled: true, mode: 'public', expiresAt: null }` state and remains enabled until `mode=off`. Missing expiries, unknown modes and out-of-range trial expiries remain invalid. Both modes use the same authenticated switch; an unsuccessful enablement attempts to restore disabled state.

The endpoint returns the active scope (`canary` or `public`), or null when disabled. The operator verifies it and the frontend requires an exact configured-mode match; legacy responses without scope fail closed. Deploy the updated Worker with `mode=init` before enabling a new build. The frontend's configured mode and token policy remain independently mandatory. A canary build still requires its reviewed wallet/pair policy; public control does not bypass that policy or turn an older build into a public desk. The frontend polls every five seconds and requires a fresh nonce-bound read before preflight and at both signing boundaries. Shutdown preserves pending receipt and recovery tracking. Production control delivery and existing/fresh-tab shutdown checks must pass before admitting live trades.

The existing `REACT_APP_OTC_ENABLED=false` deployment/reload control remains a separate route-level fallback. Do not change the compiled feature flag default to bypass an unavailable runtime control. No mainnet transaction is part of provisioning or a control-only rehearsal. Rotate the control credential by replacing the repository secret and rerunning `init`; reconcile any already-issued wallet prompts separately.
