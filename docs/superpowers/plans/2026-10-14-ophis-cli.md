# Ophis CLI Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
**Goal:** Ship `ophis`, a terminal CLI (npm `@ophis/cli` plus standalone binaries) that lets users on macOS, Linux and Windows quote, swap, place limit orders, cancel and bridge with Ophis, signing inside the terminal, with no browser.
**Architecture:** A thin command layer in a new workspace package `packages/cli` over `@ophis/sdk` (order build, partner-fee appData, referral, EIP-712 domain, hosts, receiver guards, EthFlow, preflight). The orderbook HTTP calls, token resolution and chain/RPC tables move from the private `apps/mcp-server` into `@ophis/sdk`, so the MCP and the CLI share one implementation. Signers sit behind one small interface. Bridging reuses the frontend's patched cow-sdk bridging stack and its Across subclass. Bun bundles the package into one ESM file for npm and compiles single binaries for GitHub Releases.
**Tech Stack:** TypeScript ESM, Node `^20.19.0 || >=22.12.0`, pnpm 9.12.0, viem ^2.48.8, vitest ^4.1.11, node:util parseArgs, node:readline, node:crypto, Bun (build only). M3 adds `@cowprotocol/cow-sdk@9.0.2`, `@cowprotocol/sdk-bridging@4.0.2`, `@cowprotocol/sdk-viem-adapter@0.3.18` and `@cowprotocol/sdk-cow-shed@0.3.8` (already sdk-bridging's own dependency). M4 adds `@walletconnect/sign-client@2.25.0` and `qrcode-terminal@0.12.0`.

## Global Constraints
- Node engines `^20.19.0 || >=22.12.0`; `pnpm@9.12.0`; ESM with `.js` import suffixes (repo convention).
- No U+2014 em-dash in any user-facing string, README, docs page, SKILL.md or commit message. Name only chains that `listOphisChains()` returns (never the two chains Clement excluded from copy), and never use the banned word "h-o-n-e-s-t" (hyphenated so this plan passes the same grep).
- Chains come only from `@ophis/sdk` (`listOphisChains()` = `OPHIS_FEE_CHAIN_IDS` x `OPHIS_ORDERBOOK_URLS`). `packages/cli` holds no chain, RPC or token list of its own.
- Fee: the CLI never sets a fee rate. It uses the sdk default appData (`buildOphisFullAppData`) with source `cli`. `metadata.partnerFee` must deep-equal `buildOphisAppDataPartnerFee(chainId, isStablePair)` and carry exactly ONE `volumeBps` entry (#1236 class).
- Private keys are never accepted in argv, never printed, never written unencrypted. On POSIX, files the CLI writes are 0600 and dirs 0700 (`main.ts` sets umask 077); on Windows the per-user `%APPDATA%` ACL applies and tests skip mode asserts. Prompts and summaries go to stderr. Stdout carries results only.
- RPC: custom URLs must be `https://` (`http://` only for localhost), and every client is checked with `eth_chainId` before the first read. Local-key txs send gas and fees pinned before the prompt, and under `--yes` a worst-case fee above 5% of the native balance aborts (WalletConnect wallets show their own fee).
- Every order or cancellation signature the CLI posts itself (swap, limit, cancel, submit) is recovered and compared to the signer first, and every posted appData, bridge orders included, passes `assertOphisAppData` (the #1236 invariant).
- No telemetry. Network use is limited to orderbook hosts, the Ophis token lists, the Ophis rebate indexer (`enrollOphisTrader` registers the trading wallet before each order, as agent-swap and the web app do), RPCs, the Across API (M3), the WalletConnect relay (M4) and GitHub Releases (installer).
- No paid services: no Apple notarization, no Authenticode, no paid KMS. Only free GitHub artifact attestations and npm provenance.
- CI tests never hit live chains or APIs. They inject `fetchImpl` or stub `fetch` and mock viem clients.
- New runtime deps arrive only in M3/M4, pinned to exact versions at least 7 days old. Each is loaded with dynamic `import()` and must pass supply-chain-risk-auditor before merge. They ship inside the bundle, so `npm audit` on a user machine never sees them: the repo's `security.yml` osv-scanner job (full lockfile, devDependencies included) is the audit.
- Bun is a build tool only. Pin the newest version published at least 7 days ago (`npm view bun time`; 1.4.2 on 2026-10-14) in every workflow through `oven-sh/setup-bun`, pinned to a commit SHA (`gh api repos/oven-sh/setup-bun/commits/v2 --jq .sha`).
## Review Focus
1. A token `symbol()` or list name that contains ANSI escapes or bidi characters must not be able to rewrite the confirmation summary (Task 4 pins `sanitize`).
2. On Windows, a CRLF password file, an unset `%APPDATA%` and paths with spaces must all work (Task 5 pins them).
3. If a quote goes stale while an approval tx confirms, it is re-fetched, and a worse price is never signed silently under `--yes` (Task 9 pins `refreshIfStale`).
4. `ophis swap ... --json | jq` with no TTY and no `--yes` exits 3 with a JSON error and never hangs (Tasks 3 and 5 pin it).
5. `0.1234567` USDC, `1e3` and `1,5` must error and never round (Task 4 pins it).
6. The bridge signer signs only a hook for the user's own recomputed CoW Shed whose weiroll program is one Across deposit paying the user, then an Order into that shed that still meets the confirmed minimum, and the order the bridge SDK actually posts passes the fee guard (Task 18 pins `bridgeAccount` and `guardSendOrder`).
7. `ophis submit` refuses a file whose appData was edited or carries a duplicated fee, even with a valid signature (Task 11 pins it).
## Design
**Scope (v1):** `quote`, `swap` (ERC-20 sells, native sells through EthFlow, `--exact-out`), `submit`, `wallet`, `config`, `chains` (M1); `orders`, `status`, `cancel`, `limit`, `tokens`, `balance` (M2); cross-chain through `swap --to-chain` and `bridge`, Across only (M3); WalletConnect signer (M4); binaries, installers, agent skill and docs (M5).
**Non-goals (v1):** Ledger USB (its node-hid and usb deps run install scripts on every `npm i -g`; Ledger users connect through WalletConnect and Ledger Wallet); TWAP; Safe or presign flows (`@ophis/safe-swap` covers them); natural-language mode; browser signing; NEAR Intents (it needs >= $1k per swap and an API key a public CLI cannot ship, and no real NEAR bridge has settled yet); Solidity (none, so Pashov solidity-auditor is not triggered); a self-update command (re-run the installer instead).
```
argv -> cli.ts (parseArgs, dispatch, exit codes) -> commands/*.ts
  resolve.ts (chain, token)   amount.ts (parse, min-out)   config.ts (dirs, RPC)   summary.ts
  signer.ts -> keystore | env | walletconnect      (--unsigned: no signer, JSON out)
  trade.ts  -> @ophis/sdk: buildOphisFullAppData, buildOrder, getOphisQuote, submitOphisOrder,
               ophisPreflight, buildOphisEthFlowOrder, resolveOphisToken, listOphisChains
  M3 commands/bridge.ts -> cow-sdk BridgingSdk + OphisAcrossBridgeProvider (drift-pinned copy)
```
| Signer | Select with | In binary | Notes |
|---|---|---|---|
| Keystore (Web3 Secret Storage v3) | `--keystore <name or path>`, or `config set keystore` | yes | Reads `~/.foundry/keystores/<name>` and `<config>/keystores/<name>`. Password (8+ chars for new keystores) comes from a hidden prompt or an owner-only `OPHIS_KEYSTORE_PASSWORD_FILE` |
| Env key | `OPHIS_PRIVATE_KEY` | yes | For bots and CI, from a secret manager, never typed inline. Never accepted as argv. Set together with a config keystore it is a `SIGNER_CONFLICT` |
| WalletConnect v2 | `--walletconnect` | yes | QR code in the terminal, the phone wallet signs. Ledger Wallet over WC gives Ledger clear signing |
| Unsigned | `--unsigned --owner <addr>` | yes | Prints typed data and tx requests. `ophis submit` checks and posts the signature |

| Command | Form | Key flags |
|---|---|---|
| quote / swap | `ophis quote|swap <amount> <sell> <buy> -c <chain>` | `--exact-out --slippage --min-out --max-in --unsafe-receiver --confirm-receiver --ref --approve-max --valid-for -y --to-chain`, signer flags |
| bridge | `ophis bridge <amount> <token> [dstToken] -c <src> --to-chain <dst>` | as swap |
| limit | `ophis limit <amount> <sell> <buy> --price <buy per 1 sell> -c <chain>` | `--valid-for` (minutes, default 10080) |
| orders / status / cancel | `ophis orders -c`, `ophis status <uid> -c`, `ophis cancel <uid> -c` | `--owner --count --watch --onchain` |
| tokens / balance | `ophis tokens <symbol> -c`, `ophis balance [tokens...] -c` | `--owner` |
| wallet / config / chains / submit | `wallet new|import|list|address [name]`, `config path|get|set|unset`, `chains`, `submit <file or ->` | |

Global flags: `--json`, `-y/--yes`, `--rpc <url>`, `-h`, `-v`. RPC resolution order: `--rpc` > `OPHIS_RPC_URL_<chainId>` > `config.rpc.<chainId>` > sdk `OPHIS_PUBLIC_RPCS`. Referral resolution order: `--ref` > `OPHIS_REFERRAL_CODE` > `config.ref`. Default slippage is 0.5% (the frontend's `DEFAULT_SLIPPAGE_BPS = 50`). Native sells use at least 0.5% and at least 10 min validity (the frontend's `MINIMUM_ETH_FLOW_DEADLINE_SECONDS`). Orders are valid for 30 min by default. The CLI re-quotes when a quote is older than 30 s at signing time, and `--min-out`/`--max-in` bind a swap to the quote the user saw. `--yes` never confirms a foreign receiver: that needs `--confirm-receiver <same address>`.
Exit codes: 0 ok, 1 unexpected, 2 usage, 3 aborted or needs `--yes`, 4 not found (chain, token, route), 5 upstream (orderbook, RPC, API), 6 insufficient balance, 7 order ended unfilled (`status --watch`). Under `--json`, success prints `{"ok":true,...}` and failure prints `{"ok":false,"error":{"code","message",...}}` on stdout.
**Deviations from the briefed decisions (evidence in the claims ledger):**
1. Bun bundle instead of `tsc` emit. M3 depends on three pnpm-patched cow-sdk packages (`apps/frontend/package.json:33-35`), and pnpm patches never reach npm consumers, so the patched code has to ship inside the artifact. The bundle also gives npm users zero runtime deps. `tsc --noEmit` remains the typecheck.
2. No dependency on `@ophis/agent-swap`. It is sell-only and ERC-20-only, uses a custom wallet interface and pulls in `@cowprotocol/cow-sdk ^5.9.0`. After Task 1 the sdk alone covers quote, build and submit.
3. EthFlow already exists on 10, 130 and 4663 (`ethflow.ts:48-52`). Native sells therefore work everywhere except Arc 5042, where `assertOphisOrderTokens` blocks them.
4. The sdk fee is 1 bp volume on every chain (`partner-fee.ts:41,71`), not 5 bps. CoW-hosted chains add a price-improvement entry paid to the same recipient, so the CLI pins `partnerFee` deep-equal to the sdk default (exactly one volume entry, the improvement entry neither missing nor doubled), bridge orders included, as the frontend sends them.
5. No Ledger USB in v1 (see Non-goals). `@ledgerhq/hw-app-eth` 7.11.0 was also published on 2026-10-14, under the 7-day rule, and calls Ledger's network services.

/** Uploads an appData document so the orderbook can resolve its hash (needed for EthFlow orders). */
export async function uploadOphisAppData(chainId: number, appDataHash: `0x${string}`, fullAppData: string, fetchImpl: typeof fetch = fetch): Promise<void> { assertChain(chainId);
  if (keccak256(toBytes(fullAppData)).toLowerCase() !== appDataHash.toLowerCase()) throw new Error('upload_app_data: fullAppData does not hash to appDataHash');
  const res = await timedFetch(fetchImpl, `${getOphisOrderbookUrl(chainId)}/api/v1/app_data/${appDataHash}`,
    { method: 'PUT', headers: { 'content-type': 'application/json' }, body: JSON.stringify({ fullAppData }) }, ORDERBOOK_TIMEOUT_MS, 'upload_app_data');
  if (!res.ok) throw new Error(`upload_app_data failed (${res.status}): ${truncate(await res.text())}`); }

import { formatUnits, parseUnits } from 'viem'; import { MAX_SLIPPAGE_BIPS } from '@ophis/sdk'; import { CliError } from './output.js'
const BPS = 10_000n, MAX_UINT256 = (1n << 256n) - 1n
const bad = (code: string, msg: string) => new CliError('USAGE', code, msg)
export function parseAmount(input: string, decimals: number, label = 'amount'): bigint { const s = input.trim().replace(/_/g, '')
  if (!/^(\d+(\.\d+)?|\.\d+)$/.test(s)) throw bad('BAD_AMOUNT', `${label}: "${input}" is not a plain decimal number`)
  if ((s.split('.')[1] ?? '').length > decimals) throw bad('BAD_AMOUNT', `${label}: "${input}" has more than ${decimals} decimals`)
  const v = parseUnits(s, decimals)
  if (v <= 0n || v > MAX_UINT256) throw bad('BAD_AMOUNT', `${label}: must be greater than 0`)
  return v }
export function parseSlippageBps(input: string | undefined, fallback: number): number { if (input === undefined) return fallback
  if (!/^(\d+(\.\d{1,2})?|\.\d{1,2})$/.test(input.trim())) throw bad('BAD_SLIPPAGE', `--slippage is a percent with at most 2 decimals, e.g. 0.5 (got "${input}")`)
  const bps = Number(parseUnits(input.trim(), 2))
  if (bps > MAX_SLIPPAGE_BIPS) throw bad('BAD_SLIPPAGE', `--slippage above ${MAX_SLIPPAGE_BIPS / 100}% is refused`)
  return bps }

  return cut ? `${i}.${cut}` : i }

// packages/cli/src/keystore.ts
import { createCipheriv, createDecipheriv, pbkdf2Sync, randomBytes, randomUUID, scryptSync, timingSafeEqual } from 'node:crypto'; import { existsSync } from 'node:fs'
import { homedir } from 'node:os'; import { join } from 'node:path'; import { hexToBytes, keccak256 } from 'viem'; import { privateKeyToAddress } from 'viem/accounts'
import { configDir } from './config.js'; import { CliError } from './output.js'
export interface KeystoreV3 { version: 3; id: string; address: string
  crypto: { cipher: 'aes-128-ctr'; cipherparams: { iv: string }; ciphertext: string; kdf: 'scrypt' | 'pbkdf2'
    kdfparams: { dklen: number; salt: string; n?: number; r?: number; p?: number; c?: number; prf?: string }; mac: string } }
const MAX_SCRYPT_BYTES = 512 * 1024 * 1024
const bad = (msg: string) => new CliError('USAGE', 'KEYSTORE', msg)
/** Raw UTF-8 password bytes, never normalized: geth (`[]byte(auth)`) and cast do the same, so non-ASCII passwords stay interoperable. */
function deriveKey(c: KeystoreV3['crypto'], password: string): Buffer { const pw = Buffer.from(password, 'utf8'), k = c.kdfparams, salt = Buffer.from(k.salt, 'hex')
  try { if (k.dklen !== 32) throw bad('unsupported keystore parameters (dklen must be 32)')
    if (c.kdf === 'scrypt') { const { n = 0, r = 0, p = 0 } = k
      if (!(n > 1 && (n & (n - 1)) === 0 && r > 0 && p > 0 && p <= 16 && 128 * n * r <= MAX_SCRYPT_BYTES / 2)) throw bad('unsupported keystore parameters (scrypt)')
      return scryptSync(pw, salt, 32, { N: n, r, p, maxmem: MAX_SCRYPT_BYTES }) }
    if (c.kdf === 'pbkdf2') { if (k.prf !== 'hmac-sha256' || !k.c || k.c > 10_000_000) throw bad('unsupported keystore parameters (pbkdf2)')
      return pbkdf2Sync(pw, salt, k.c, 32, 'sha256') }
    throw bad(`unsupported keystore kdf "${String(c.kdf)}"`)
  } finally { pw.fill(0) } }
const macOf = (dk: Buffer, ct: Buffer) => Buffer.from(hexToBytes(keccak256(Buffer.concat([dk.subarray(16, 32), ct]))))
/** Zeroes the derived key and plaintext buffers. Known limit: the returned hex string (and viem's copy) cannot be wiped in JS. */
export function decryptKeystore(json: unknown, password: string): `0x${string}` { const ks = json as Partial<KeystoreV3> & { Crypto?: KeystoreV3['crypto'] }
  const c = ks?.crypto ?? ks?.Crypto
  if (ks?.version !== 3 || !c || c.cipher !== 'aes-128-ctr') throw bad('not a version 3 aes-128-ctr keystore')
  const dk = deriveKey(c, password), ct = Buffer.from(c.ciphertext, 'hex'), want = Buffer.from(c.mac, 'hex'), got = macOf(dk, ct)
  let pk: Buffer | undefined
  try { if (want.length !== got.length || !timingSafeEqual(want, got)) throw bad('wrong password (MAC mismatch)')
    const d = createDecipheriv('aes-128-ctr', dk.subarray(0, 16), Buffer.from(c.cipherparams.iv, 'hex'))
    pk = Buffer.concat([d.update(ct), d.final()])
    if (pk.length !== 32) throw bad('keystore does not hold a 32-byte key')
    return `0x${pk.toString('hex')}`
  } finally { dk.fill(0); pk?.fill(0) } }
/** geth StandardScryptN parameters (n=262144, r=8, p=1): readable by cast and geth. */
export function encryptKeystore(pk: `0x${string}`, password: string, opts: { n?: number } = {}): KeystoreV3 { const salt = randomBytes(32), iv = randomBytes(16)
  const crypto: KeystoreV3['crypto'] = { cipher: 'aes-128-ctr', cipherparams: { iv: iv.toString('hex') }, ciphertext: '', kdf: 'scrypt',
    kdfparams: { dklen: 32, n: opts.n ?? 262_144, r: 8, p: 1, salt: salt.toString('hex') }, mac: '' }
  const dk = deriveKey(crypto, password), c = createCipheriv('aes-128-ctr', dk.subarray(0, 16), iv)
  const ct = Buffer.concat([c.update(Buffer.from(pk.slice(2), 'hex')), c.final()])
  crypto.ciphertext = ct.toString('hex'); crypto.mac = macOf(dk, ct).toString('hex'); dk.fill(0)
  return { version: 3, id: randomUUID(), address: privateKeyToAddress(pk).slice(2).toLowerCase(), crypto } }
export const keystoreDirs = (dir = configDir(), home = homedir()): [string, string] => [join(dir, 'keystores'), join(home, '.foundry', 'keystores')]

    if (!nameOrPath.split(/[\\/]/).includes('..') && existsSync(nameOrPath)) return nameOrPath
    throw new CliError('NOT_FOUND', 'KEYSTORE_NOT_FOUND', `no keystore file at ${nameOrPath}`) }
  if (!/^[A-Za-z0-9_-][A-Za-z0-9._-]{0,63}$/.test(nameOrPath)) throw bad('keystore name: letters, digits, ".", "_", "-" only')
  for (const d of dirs) if (existsSync(join(d, nameOrPath))) return join(d, nameOrPath)
  throw new CliError('NOT_FOUND', 'KEYSTORE_NOT_FOUND', `no keystore named "${nameOrPath}" in ${dirs.join(' or ')}`) }

/** Estimates once and pins gas and fees into each tx, so a custom RPC cannot inflate them between the summary and the send. */
export async function gasPlan(client: Pick<PublicClient, 'estimateFeesPerGas' | 'estimateGas' | 'getBalance'>, from: `0x${string}`, txs: Tx[], yes: boolean): Promise<{ txs: Tx[]; fee: bigint }> {
  if (!txs.length) return { txs, fee: 0n }
  const { maxFeePerGas, maxPriorityFeePerGas } = await client.estimateFeesPerGas()
  // An approve that follows a USDT reset cannot be estimated before the reset mines: 100k gas covers any ERC-20 approve.
  const pinned = await Promise.all(txs.map(async (t, i) => ({ ...t, maxFeePerGas, maxPriorityFeePerGas,
    gas: await client.estimateGas({ account: from, ...t }).then((g) => (g * 12n) / 10n, (e) => { if (i === 0) throw e; return 100_000n }) })))

import { readFileSync } from 'node:fs'; import { keccak256, toBytes } from 'viem'
import { addressesEqual, getOphisOrderDomain, isOphisStablePair, ORDER_TYPED_DATA_TYPES, submitOphisOrder, type BuiltOrder } from '@ophis/sdk'; import { CliError, emit, usage } from '../output.js'
import { confirm } from '../prompt.js'; import { assertOphisAppData, assertSignedBy, enroll } from '../trade.js'; import { confirmReceiver } from './trade.js'; import type { Command } from '../cli.js'
export interface Submission { chainId: number; from: `0x${string}`; order: BuiltOrder['order']; fullAppData: string; signature: `0x${string}`; signingScheme: 'eip712' }
export function readSubmission(raw: string): Submission { let j: Record<string, unknown>
  try { j = JSON.parse(raw) } catch { throw usage('input is not JSON') }
  const s = (j.submit ?? j) as Partial<Submission>
  if (typeof s.signature !== 'string' || !/^0x[0-9a-fA-F]{130}$/.test(s.signature)) throw usage('add the 65-byte "signature" (0x...) to the submit object')
  if (s.signingScheme !== undefined && s.signingScheme !== 'eip712') throw usage('only eip712 signatures are accepted (Safe users: @ophis/safe-swap)')
  if (typeof s.chainId !== 'number' || !s.order || typeof s.from !== 'string' || typeof s.fullAppData !== 'string') throw usage('expected { chainId, from, order, fullAppData, signature }')
  return { ...(s as Submission), signingScheme: 'eip712' } }
/** The file may have been edited between --unsigned and signing (an agent, a paste): the hash, the fee invariant and the signer all re-checked. */
export async function verifySubmission(s: Submission): Promise<void> { const o = s.order
  if (keccak256(toBytes(s.fullAppData)).toLowerCase() !== String(o.appData).toLowerCase()) throw new CliError('USAGE', 'APPDATA_MISMATCH', 'fullAppData does not hash to order.appData; the file was edited')
  assertOphisAppData(s.fullAppData, s.chainId, isOphisStablePair(s.chainId, o.sellToken, o.buyToken))
  await assertSignedBy({ domain: getOphisOrderDomain(s.chainId), types: ORDER_TYPED_DATA_TYPES, primaryType: 'Order',
    message: { ...o, sellAmount: BigInt(o.sellAmount), buyAmount: BigInt(o.buyAmount), feeAmount: BigInt(o.feeAmount) } } as never, s.signature, s.from) }
const readStdin = async () => { let d = ''; for await (const c of process.stdin) d += c; return d }
export const submit: Command = async ([src], flags, io) => { if (!src) throw usage('usage: ophis submit <file|-> [--unsafe-receiver <addr> to allow a non-owner receiver]')
  const s = readSubmission(src === '-' ? await readStdin() : readFileSync(src, 'utf8'))
  await verifySubmission(s)
  const o = s.order
  if (!io.json) io.err([`Chain      ${s.chainId}`, `Sell       ${o.sellAmount} atoms of ${o.sellToken}`, `Get        at least ${o.buyAmount} atoms of ${o.buyToken}`,
    `Receiver   ${o.receiver}${addressesEqual(o.receiver, s.from) ? ' (you)' : '  <-- NOT the signer'}`, `Expires    ${new Date(o.validTo * 1000).toISOString()}`].join('\n'))
  await confirm('Submit this signed order?', flags)
  const allowCustomReceiver = flags['unsafe-receiver'] !== undefined && addressesEqual(flags['unsafe-receiver'], o.receiver)
  if (allowCustomReceiver && !addressesEqual(o.receiver, s.from)) await confirmReceiver(flags, o.receiver, s.from) // --yes alone never confirms a foreign receiver
  await enroll(io, s.from)
  try { const uid = String(await submitOphisOrder({ ...s, allowCustomReceiver })); emit(io, { uid, chainId: s.chainId }, `order placed: ${uid}`) }
  catch (e) { throw new CliError('UPSTREAM', 'SUBMIT_FAILED', (e as Error).message) } }

/** EthFlow orders are indexed from the createOrder event; a rejected placement (stale quote id) leaves the ETH escrowed until cancelled. */
export async function awaitPlacement(get: () => Promise<OphisOrder>, uid: string, chainId: number, wait: () => Promise<unknown> = () => sleep(5000), tries = 12): Promise<void> {

## Decisions for Clement
1. Fee: the CLI uses the sdk default (1 bp volume, plus the price-improvement policy on CoW-hosted chains), not 5 bps. Confirm it, or name a CLI rate, which would need a new sdk option.
2. `OPHIS_PRIVATE_KEY`: the agent-skills policy rejects raw env keys, but the CLI allows one for bots (README: secret manager only), and it conflicts with a configured keystore instead of silently winning. Keep it or drop it.
3. WalletConnect: create a free Reown project "Ophis CLI" (public id, empty allowlist) or reuse the frontend's id.
4. Ledger USB is out of v1 (install scripts on every npm install, a same-day hw-app-eth). Ledger users go through WalletConnect and Ledger Wallet. If wanted later: a separate opt-in `@ophis/cli-ledger` package.
5. Bridge v1 is Across from Ethereum, Arbitrum and Base only. NEAR Intents and the flag-gated extra sources wait for frontend proof.
6. Installers are served from `ophis.fi/install.sh` and `ophis.fi/install.ps1` (landing `public/`).
7. Safety defaults that trade convenience: approvals raise the current allowance by the order amount (so open limit orders keep theirs) instead of approving exactly; under `--yes` a network fee above 5% of the native balance aborts; `--yes` alone never confirms a foreign receiver.
